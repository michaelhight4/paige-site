# Kilumen: dev notes

2D "128-bit" creature battler (Gary's design doc, `/workspace/kilumen/Kilumen_design_doc.pdf`, "DD" below). PROJECTS.md lists it as "Next after Lifeline". Paths are relative to `/workspace/kilumen` unless they start with `/`.

## 1. Architecture
- **Engine:** none. The game is static HTML + native ES modules drawn on a canvas, with no build step for the game itself. Movement is on a grid with integer zoom and a fixed tick (OVERWORLD_DEV.md). Speeds are walk 15 ticks/tile, run 7.5, bike 5 (OVERWORLD_DEV.md).
- **Run:** `npm start` (`python3 -m http.server 8080`), then open `http://localhost:8080/`. ES modules need http://. URL params are listed in `OVERWORLD_DEV.md`: map, x, y, facing, debug, zoom, touch, flags, save=0, reset=1, hour, phase, timescale, weather, clouds, life, motion, plus `?platform=pc|mobile`, `?depth=0|1`, `?depthstrength=`, `?battle=shell|sd`, `?dev=1`.
- **Tests:**
  - `npm test` runs `node --test` over overworld, platform, batch3, depth, battle, save_props and libs (package.json).
  - Browser checks: `node tests/touch_e2e.mjs` (real touch), `tests/platform_shots.mjs`, `tests/ui_pass_shots.mjs`, `tests/life_perf.mjs`, `tests/battle_touch_e2e.mjs`.
  - `npm run shots` runs `tests/shots.mjs`.
- **Battle engine build:** `node tools/build_battle_engine.mjs [--check]`. It uses esbuild to bundle `vendor/battle-sim` (TypeScript) into `src/battle/engine.js`, and `--check` runs tsc first (header of tools/build_battle_engine.mjs).
- **Folders (`src/`):**
  - `main.js` (boot and dev params), `config.js` (start flags), `platform.js` + `platform/pc.json` / `platform/mobile.json`, `landscape.js`
  - `overworld/`: constants, map, movement (GridMover), camera, tileset, assets, renderer, debug, dialog, lines, clock, lighting, living, npcs, pathing, props, palette, input, `depth.js` + `depth.json`, `save.js` + `save_backend.js`, and `overworld.js` (the scene, with the `window.kilumen` test API)
  - `battle/`: `battle.js` (glue: party/bag ⇄ engine sets, pure and seeded), `engine.js` (built), `ui_sd.js`, and `data/` (creatures, elements, skills, rules, index)
  - `ui/`: ui.js, data.js, `devpanel.js` (lil-gui, dev only), theme.css, ui.css
  - `audio/`: audio.js (howler + ZzFX), PLACEHOLDERS.md
  - `vendor/`: howler, zzfx, easystar, idb-keyval, lil-gui, lrud-spatial, sortablejs
- **Other folders:**
  - `vendor/battle-sim`: the MIT Showdown/pkmn fork, with LICENSE and LICENSE.pkmn
  - `vendor_staging/`: libraries pulled for review, see MANIFEST.md
  - `art/` (characters, ui, world), `text/`, `design/`, `docs/`, `tools/`, `shots/`, `refs_gary/`
- **Save:** key `kilumen.save.v1`, plus one backup. The key name is kept on purpose, and the version lives inside the save. `SAVE_VERSION = 2`, and old saves step through `MIGRATIONS` one version at a time. The v2 blocks (saveId, coins, bag, archive, kilindex, tasks, company) are format only: nothing reads or writes them yet (header of `src/overworld/save.js`). The backend is IndexedDB through idb-keyval, mirrored to localStorage synchronously so iOS pagehide can't lose a write. At load, the newer `savedAt` wins (header of `src/overworld/save_backend.js`).
- **Deploy path:** not published. The branch `dev/overworld-v1` is local only and has **no git remote**; there are 4 commits and about 169 changed or untracked paths (`git status`, Oct 22 ~10:20 PM CT). The checklist rule "Art in progress stays local" applies until Gary approves. A paigegames.net card exists in `/workspace/domain_hub/shots/kilumen_card` *(inferred: a site card was prepared; the publish state is not confirmed)*.

## 3. Gotchas and bugs (symptom → cause → fix)
- **Trainers "win" by talking** → `hooks.onBattle` etc. are null in overworld.js, so there is no battle, capture, party, bag, shop or encounter roll → the battle engine behind `?battle=sd` plus the shell battle, with P0 gaps listed. Source: design/MECHANICS_PARITY.md (main finding, top 10 P0).
- **Showdown has no catch, XP or level-up events** → Kilumen's wrapper must supply them. `xpForLevel` in src/battle/battle.js is marked PLACEHOLDER [B20]. Source: src/battle/battle.js.
- **The empty dialog name bar showed on ask prompts** → a skin rule `display:inline-block` overrode the `hidden` attribute → pair every `display` skin rule with `[hidden]{display:none}`. Never put `overflow:hidden` on touch buttons, because it clips the 44px `::after` hit areas. Source: checklist line ~368.
- **Touch input stuck or ghosting** → held input wasn't cleared on blur/pagehide/rotate → `Input.guardTouchPage`, `Input.dirQueued` (sub-frame taps), `touch-action:none`, presses on pointerdown. Proven by tests/touch_e2e.mjs (CDP multi-touch in Chromium plus WebKit iPhone). Source: checklist line ~359.
- **Art with baked shadows looks wrong** under the engine depth pass → art must not bake shadows. The depth pass (depth.js/depth.json) draws them in the time-of-day shadow colour `grade.shadowDst`. Source: checklist line ~355; depth.json `note`.
- **depth.json is shared by both platforms.** There is no per-platform depth block. The dev panel edits it live and exports it, but it never writes pc.json or mobile.json. Source: header of src/ui/devpanel.js.
- **The save key says v1 but holds v2.** This is intentional, so existing saves are still found. Don't "fix" the key name. Source: src/overworld/save.js.
- **iOS Safari kills the tab before an IndexedDB write lands** → mirror the save to localStorage synchronously and let the newer `savedAt` win at load. Source: src/overworld/save_backend.js.
- **All audio is placeholder.** Music is a seeded triangle loop and SFX are ZzFX tones. To ship real audio, swap the URLs and sprites and keep the ids. Saltmere and Cindervale tracks are unused because those zones have no maps. Source: src/audio/PLACEHOLDERS.md.

- **Platform profiles:** one ScriptableObject per platform (PC, Mobile) holding zoom table, HUD layout, controls and prompts, safe areas. Pick it once at boot and never cross-read. The JSON shape to copy is in src/platform/*.json.

- **Battle core as a pure, seeded module:** no rendering or timers inside it, so it can run on a server. In Unity, use a plain C# assembly with no `UnityEngine` references. Re-check the licence before porting any Showdown logic: MIT allows it if the notice is kept.
- **Save:** an in-save `version`, step-by-step migrations, one main save plus one backup, and property tests on the migrations (fast-check here; FsCheck or a hand-rolled fuzz for C#).

- **Real-touch tests, not mouse emulation:** in Unity, use the Input System's touch simulation plus a device build test. Keep 44×44 pt hit areas, and clear held input on focus loss.
